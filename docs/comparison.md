# How this compares

Read on **2026-10-22** (previous reading: 2026-10-11), from each project's own README or landing page (no blog posts, no sponsored write-ups). The pages were read through a page-extraction tool that answers questions about a page, so this is a second-hand reading of each README: quotes are paraphrased, and "not stated" means the answer did not give it. "Not verified" means the page does not say and no other primary source was checked. These are young, mostly single-maintainer projects, including this one, and they change fast (three of the six others moved between the two readings): none of this is an endorsement, and a thin or missing cell is not evidence of absence, only that the page does not say.

| Project | Approval lives | Covers | Granularity | Out-of-band channel | Observe mode | Audit log | Secrets kept from the model |
|---|---|---|---|---|---|---|---|
| **keeper** (this repo) | Separate user (`_keeper`/`keeper` daemon); go-gate alone is same-process | Every tool call, via go-gate's classifier | Per plan (scope + TTL), checked call by call | Yes — a second Telegram bot the agent cannot read | Yes (`--observe`); the installer's default is block | Plain JSON lines (`log.jsonl`); not hash-chained or signed | **No.** Output filtering is secret-guard's job, in the agent's own process (keeper/README.md, "What the keeper does and does not guarantee") |
| [tarides/sudo-proxy](https://github.com/tarides/sudo-proxy) | Same terminal as the human approver; a separate machine when used over SSH | Its own `execute` tool (shell), not other tool calls; every command, privileged or not | Per command, no auto-approve | No — the keypress is in the same terminal flow, not a separate channel | Not stated | Only with `-v`; format not stated | Yes, claimed: no password stored, "sanitized allowlist" environment |
| [luisgf/infrabroker](https://github.com/luisgf/infrabroker) | Separate process (`cmd/signer`) in server mode; same process in local/quickstart mode | SSH and Kubernetes only | Per command (SSH); per verb/resource/namespace (k8s) | **Changed:** yes, an approval bridge posts pending approvals to Slack (Socket Mode) with Allow / Deny buttons; earlier reading: "channel not named" | Yes, action budgets ("observe or enforce"); dry-run for commands | Yes, strong: append-only, Ed25519-signed, SHA-256-chained | Yes, explicit: ephemeral credentials never enter the model's context; **changed:** credentials inline in commands are also masked in audit logs, recordings and approval notifications (best-effort pattern matching, not DLP) |
| [BrightbeamAI/chap](https://github.com/BrightbeamAI/chap) | Not specified — coordinator can be "embedded in your own process or run as a server" | Work artefacts (diffs, tasks, reviews); an MCP gate exists but its scope isn't detailed | Per artefact (e.g. a diff), not per command | Not described | Yes, named ("shadow and trial modes"), no details given | Yes, strong: hash-chained, optional transparency log | Not verified |
| [lacs-project/sysknife](https://github.com/lacs-project/sysknife) | Separate process **and** separate user (privileged daemon) | A catalogue of typed actions only (140+ on Fedora and Ubuntu; a daemon table lists 192) — "the AI never supplies a command" | Per step, with a transaction id; `--yes` can skip up to a risk ceiling | Yes, a separate command (`sysknife approve <id>`) that the human runs; the earlier reading quoted it as "a channel the model does not sit on" (not re-checked word for word); Telegram is roadmap only | `--dry-run` (plan only) and a read-only observer role | Yes, strong: tamper-evident chain, HMAC-SHA256 / Ed25519-signed | Not stated |
| [OthmaneBlial/term_mcp_deepseek](https://github.com/OthmaneBlial/term_mcp_deepseek) | Local web UI on the same machine; not stated as a separate OS user | Shell commands; coverage of non-shell tool calls not verified | Not stated | Not stated — approval is in the same local UI | **Changed:** `inspect` mode is read-only by default and blocks writes; earlier reading: "does not say it blocks execution" | Yes: signed receipts per action | Not stated |
| [Proofpane](https://github.com/Proofpane/releases) | Local MCP daemon on the same machine; **the daemon is closed-source** (the repository is a download mirror) | Claims coding agents, workflow tools and LLM APIs; its own coverage view shows which MCP servers run direct ("ungoverned") | Not stated | "Human-approval gates" (via pairing with a Proofpane organisation); channel not documented | Not stated beyond a `--dry-run` for its usage sync | Claimed: SHA-256 hash-chained, Ed25519-anchored — **not verifiable, the daemon's code is proprietary** | Claimed: a secret in a file read is masked before the model sees it, locally — **not verifiable, closed-source** |

Latest activity seen on the pages: sudo-proxy 16/10, infrabroker 21/10, chap 20/10, sysknife 22/10 (v0.26.0), term_mcp_deepseek 27/08, Proofpane 30/09.

**Where others are stronger than this project, plainly:** infrabroker and sysknife sign and hash-chain their audit log, and (on paper) chap and Proofpane claim hash-chained logs, Proofpane's signed as well and not verifiable; keeper's `log.jsonl` is a plain, unsigned file an operator with disk access could edit. sysknife's typed-action catalogue is a stronger guarantee than go-gate's heuristic classifier — "the AI never supplies a command" closes a whole class of disguise this project can only chase case by case (see [go-gate/test_disguise.py](../go-gate/test_disguise.py)). infrabroker states outright that secrets never enter the model's context; this project does not make that claim for keeper itself; secret-guard masks known patterns in the output of the commands and file reads it is wired into, in-process, as a safety net, and gives no guarantee that no secret reaches the model.

**Not verified:** chap gives no detail on its out-of-band channel, MCP-gate scope or model secrecy; sysknife and term_mcp_deepseek say nothing about what reaches the model; Proofpane's audit-log and secret-masking claims could not be checked past its README, since the daemon implementing them is proprietary. LangGraph's `interrupt()` was looked at on 2026-10-11 and left out of the table: its official documentation could not be reached, and a secondary summary is not enough to compare it fairly.
